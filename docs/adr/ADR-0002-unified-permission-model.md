# ADR-0002：权限模型合并为单一工具映射表，角色降级为预设包

- 状态：定稿
- 日期：2026-10-30
- 关联：[research/01](../research/01-v2-design-review.md) A2/A3；[architecture/03](../architecture/03-permission-and-approval.md)

## 背景

v2 同时存在两套决策体系：§5.2 RBAC+ABAC 角色策略引擎与 §6 四维审批 + 工具默认映射表，二者无优先级与冲突消解规则（角色说 allow、映射表说 ask 时无答案）；角色 YAML 示例还存在非法语法（重复键），说明配置缺 schema 校验。单用户桌面应用引入完整 ABAC 引擎也属过度设计。

## 决策

1. **工具默认映射表是权限判定的唯一事实源**；每个工具注册必须声明映射行，禁止未声明默认值。
2. **角色（preset）= 映射表的一组收紧覆盖 + 默认条件**（路径前缀、时间窗等），以 YAML 声明、启动时 schema 校验，非法即拒绝加载整份配置。
3. 预设**只能收紧不能放宽**：不能把 `ask` 改 `allow`、不能覆盖 `deny` 行、不能扩大作用域。
4. 冲突消解规则固定：多规则并存取**最严者**（`deny > ask > allow`）；作用域取最小；条件取交集。
5. 独立的 RBAC/ABAC 引擎包不存在；条件能力并入四维模型的条件维度（DIM3）。

## 理由

- 单一事实源使任意调用可静态推出唯一判定，权限引擎成为纯函数、可表驱动 golden test。
- 备选"保留双体系 + 优先级表"：优先级表会随维度增加而组合爆炸，且仍解释不了"为什么两个系统"。

## 后果

- 积极：砍掉一套引擎的实现与测试成本；判定可预测、可审计。
- 代价/义务：多主体/组织级隔离需求出现时需重新评估（当前产品定位明确单用户，不构成近期风险）。
- 触发重新评估条件：引入多用户或远程会话共享时。
