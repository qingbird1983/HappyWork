# ADR-0009：前端信息结构以 ZCode 为参照物

- 状态：定稿
- 日期：2026-10-30
- 关联：[research/03](../research/03-zcode-ui-reference.md)；[ADR-0007](ADR-0007-frontend-react.md)；roadmap Backlog"UI/UX 精修"（灰盒策略）；[standards/06](../standards/06-security.md) §6

## 背景

UI 策略已定"前期灰盒、后期精修"（roadmap Backlog），但灰盒阶段仍需对齐**信息结构**（呈现什么信息、怎么组织）。所有者明确偏好 ZCode 桌面客户端的操作习惯，指定其为参照物（所有者持有其本地源码；结构观察见 research/03）。

## 决策

1. 前端信息结构（会话流、工具调用块、审批弹窗、输入区的信息组织）**以 ZCode 为参照**；灰盒阶段复刻其信息结构，不做视觉设计。
2. **参照红线**：只借鉴信息结构与交互习惯；**不复制其任何代码、组件实现与视觉资产**（private 许可项目，standards/06 §6 / 07 §5）；HappyWork 实现全部原创。
3. **作用域语义不照搬**：审批作用域按本项目 ADR-0002/0003 执行（session 绑 matchKey、persistent 二次确认），严于参照物的 allowAlways 口径。
4. **截图索取流程**：需要像素级/交互细节参照时，由 AI 会话在当轮明确提出需求（哪个界面、哪个状态）→ 所有者提供真实截图（投料 `briefs/`）→ 观察结论沉淀回 research/03"补充"节，截图用完即弃。

## 理由

- 所有者日常使用 ZCode，操作习惯偏好即产品需求；参照成熟客户端可避免闭门造车。
- research/03 证实两者模型高度同构（审批选项结构、工具块摘要/展开均一一对应），参照成本低。

## 后果

- 积极：灰盒阶段信息结构有明确基准，Phase 1/2 前端设计稿可直接引用 research/03。
- 代价/义务：原创实现不得近似到"翻译级照搬"（结构同构、代码与样式独立）；截图依赖所有者配合，需求要在会话中明说。
- 重新评估条件：参照物结构性与本项目安全基线冲突（以本项目架构文档为准），或所有者改变偏好。
