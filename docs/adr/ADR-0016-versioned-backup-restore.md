# ADR-0016：文件备份版本化，恢复可再撤销，新建文件可撤销创建

- 状态：定稿（2026-10-30，随 Phase 4 立项放行）
- 日期：2026-10-30
- 关联：[architecture/04](../architecture/04-security-and-hooks.md) §备份式回滚/操作后校验；[phase-4-audit-rollback-signing.md](../roadmap/phase-4-audit-rollback-signing.md)；[design.md](../design/phase-4/design.md) §5；[ADR-0005](ADR-0005-mvp-security-downgrade.md)

## 背景

Phase 2 的 `write_file` 在覆盖前把原文件复制到 `backups/<session>/<相对路径>`，同一文件再次覆盖会**覆盖旧备份**；新建文件完全没有记录；没有恢复入口，也没有写后内容校验。结果是"备份"只能退回上一次，无法回退多步，也无法撤回 Agent 新建的文件，与"备份式回滚"的承诺不符。

完整文件系统快照已按 ADR-0005 排除（跨平台不可行、成本高）。Phase 4 在文件级备份上补齐版本、恢复与校验，但不扩张为快照。

## 决策

1. **每次覆盖写生成一个版本**：备份文件存 `backups/<session>/<rel>/v000001-<id>.bak`，元数据入 `file_backups`（rel_path、kind、reason、version、mode、size、backup_sha256、written_sha256、时间、restore_of）。
2. **新建文件也记录**：`kind=create`，记录目标路径、创建时内容 hash；不复制文件（无旧内容）。
3. **保留与容量**：每个 `(session, rel_path)` 保留最近 **20** 个版本（含恢复前的安全副本）；备份区全局**软上限 512 MiB**；超限拒绝新的覆盖备份/安全副本，并审计 `backup/quota`。新建不受上限影响；撤销创建不因上限被拒。
4. **恢复语义**：恢复所选版本前，先为当前目标创建 `pre_restore` 版本（目标不存在则准备 `restore_create` 记录）；恢复后原记录标 `restored_at`，安全副本 `restore_of` 指向它。恢复本身可再恢复/撤销。
5. **撤销创建**：仅当目标仍存在且当前 SHA-256 等于创建时 `written_sha256` 才允许；移动到 `discarded/`（跨卷则复制 + fsync + 删除），**不直接 unlink**；文件已不存在时幂等成功。
6. **写后校验**：目标写入后重读计算 SHA-256；不一致时覆盖写自动用刚创建的版本回滚，新建则移入 `discarded/`，返回失败并审计。备份副本写入前也校验 hash。
7. **路径与并发**：恢复/撤销只在会话非运行态允许；每次都重新 `workspace.Resolve` + `Rel` 复核，拒绝越界、敏感路径、符号链接/junction、目标为目录；备份相对路径必须落在备份根内。
8. **不做完整快照、批量恢复、跨设备同步、OS 回收站集成**；删除工具仍不在本期。完整快照留 Backlog，立项须 ADR。

## 理由

- 单版本备份在 Agent 连续改写时几乎没有恢复价值；版本化才能覆盖真实工作流。
- 恢复前留安全副本，使"恢复"本身也可撤销，避免二次误操作。
- 新建文件是常见副作用；只支持覆盖回滚会留下"Agent 创建的文件无法撤回"的缺口。移入备份区而非删除，保留最后的人工找回通道。
- 写后校验把"写了"与"写对了"分开；磁盘损坏、编码/权限异常不再被当作成功。
- 20 版/512 MiB 是桌面单用户的量级折中：足够覆盖一次任务的多步改写，又不至于让备份区无限膨胀。

## 后果

- 积极：同一文件可回退多步；恢复可撤销；新建可撤销；写后内容有 hash 证据；备份元数据可审计。
- 代价：每次覆盖多一次复制与 hash；备份区可能达到数百 MiB；恢复/撤销接口与 UI 增加；跨卷移动有复制峰值。
- 限制：不是快照，无法恢复未经过 `write_file` 的外部修改；备份元数据可被本机全权限用户篡改（恢复时校验 hash 但非安全边界）；软上限是快照检查，不是硬配额；路径残窗仍在，Phase 5 沙箱关闭。
- 重新评估条件：备份区频繁触顶、需要整目录回滚、或引入删除工具/OS 回收站时，另立 ADR 评估快照、配额预留或回收站集成。
