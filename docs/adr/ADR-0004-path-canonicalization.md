# ADR-0004：客体路径强制规范化前置，堵住前缀检查逃逸

- 状态：定稿
- 日期：2026-10-30
- 关联：[research/01](../research/01-v2-design-review.md) B1/D；[architecture/03](../architecture/03-permission-and-approval.md) §路径规范化管线

## 背景

v2 的 hash 锁定锁的是**参数字符串**，不是参数指向的资源。路径类客体存在经典逃逸向量：symlink / Windows junction（审批展示 `workspace/docs/a.txt`，执行时指向 `~/.ssh/id_rsa`）、Windows 大小写不敏感、8.3 短名（`PROGRA~1`）、`..` 拼接、UNC 路径。"工作区内才放行"的前缀检查若不做规范化即形同虚设。

## 决策

所有作为权限客体的路径，**必须在策略评估之前**完成规范化管线：

1. `filepath.Clean`（消 `..` 与冗余分隔符）；
2. `filepath.EvalSymlinks`，失败即拒绝；解析后**再次**校验仍在允许前缀内（防链接目标逃逸）；
3. Windows：大小写归一；拒绝 8.3 短名（检测 `~`+数字模式）与 junction；UNC 一律视为工作区外；
4. 工作区根在会话启动时规范化一次并固定；中途变化视为新会话；
5. 域名客体同理：小写化、去尾点、Punycode 归一后再做白名单匹配。

规范化结果写入 finalArgs（审计同时记录原始值与规范化值）；matchKey 与 execHash 均基于规范化后参数。规范化单独成包（`permission/canonpath`），配模糊测试。

## 理由

- 权限三元组的"客体"必须是真实资源而非字符串；这是前缀类条件可信的前提。
- 备选"执行时再校验"：审批展示与执行校验之间仍有窗口，且审批决策本身基于错误客体。

## 后果

- 积极：前缀条件、matchKey、审批展示三者语义一致；逃逸向量集中一处防御、集中测试。
- 代价/义务：每次评估的 EvalSymlinks 开销（按会话缓存缓解）；Windows 特有规则需持续跟踪新向量。
- 重新评估条件：规范化管线出现无法在包内解决的平台差异时。
