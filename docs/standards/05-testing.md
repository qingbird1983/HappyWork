# 规范 05：测试与验收

- 状态：定稿（2026-10-30 按 Go 项目回填 §1 分层表）
- 日期：2026-10-30

## 1. 测试分层（已按 Go + Wails 项目回填）

| 层 | 对象 | 手段 |
|---|---|---|
| 单元 | 模块内部逻辑（权限判定、状态机、规范化管线、预算） | Go 惯例：`_test.go` 随源码同包；权限引擎用表驱动 golden tests（见 [architecture/04](../architecture/04-security-and-hooks.md) §测试基线） |
| 集成 | 模块间契约（Actor↔Runner↔存储、审批管道、TOCTOU 演练） | `internal/` 跨包测试 + `tests/` 目录（`//go:build integration` 标签） |
| 契约/协议 | Provider API / MCP / SQLite 迁移的行为等价性 | **fixture 录制回放**（`fixtures/`，禁 CI 直连外部服务）；JCS 一致性 fuzz |
| UI / 端到端 | 用户可感知行为（渲染安全、审批弹窗、单实例锁） | 三平台按验收场景人工执行；自动化 E2E 后续评估 |
| 验收 | 阶段交付 | 逐条执行 phase 文档"验收场景" + 记入报告 |

## 2. 硬性测试义务（不达不算完成）

1. **复现先行**：修 bug 必须先写"能复现的失败测试"，再修复；该测试永久保留。
2. **外部契约 fixture 化**：涉及外部 API/格式的，正常路径 + 错误/重试 + 取消/中断三类路径都要有用例；fixture 入 `fixtures/`，来源与抓取日期在文件头注明。
3. **格式兼容**：对外文件格式定稿后，历史版本样例入 `fixtures/`，CI 断言"旧样例可读且语义不变"。
4. **崩溃/中断安全**：涉及持久化写入的模块必须有"写入中途被杀后数据可读/可恢复"用例。
5. **权限/安全负路径**（如适用）：越权用例清单化，全部必须"拒绝且留痕"。

## 3. 确定性与可复现

- 时间、随机源、外部 id 一律注入（可替换），保证测试可复现。
- 禁止测试访问网络、依赖外部服务状态；外部交互一律回放/打桩。
- 例外边界（[ADR-0008](../adr/ADR-0008-deepseek-test-provider.md)）：开发期**真机联调**（会话内显式触发）授权使用真实 Provider（DeepSeek）；自动化测试套件与 CI 仍禁止外连——真机联调不属于测试套件，其结果不作为回归依据。

## 4. 验收流程

- 每阶段验收 = 逐条执行 phase 文档"验收场景" + 《阶段进度报告》记录结果。
- 验收一票否决项：phase 文档中标注"一票否决"的场景；未通过不得打 `phase-N.end` tag。
- 覆盖率：核心模块行覆盖率目标 ≥ 70%（报告披露、不设卡）；不达标的模块在进度报告说明原因。

## 5. 回归纪律

- flaky 测试即修或隔离（标记 ignore + 登记问题），禁止长期带 flaky 绿灯。
- 门禁命令固定为 §1 表格中的组合，CI 与本地一致；门禁输出日志不入库。
