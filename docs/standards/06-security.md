# 规范 06：安全与隐私

- 状态：定稿
- 日期：2026-10-30

## 1. 威胁模型（一句话）

本项目运行在本机用户全权限下，执行模型驱动的本地工具、MCP 子进程与 Hook，渲染不可信的模型/外部内容——安全设计围绕"默认最小能力，一切显式授权"，细则见 [architecture/03](../architecture/03-permission-and-approval.md)、[04](../architecture/04-security-and-hooks.md)。

## 2. 仓库卫生

- 密钥/凭证/令牌**严禁**入库：`.env*` 已 gitignore；示例文件只允许 `.env.example` 占位符。
- 个人绝对路径（`C:\Users\<名>` 等）不入库；文档引用外部项目用 URL 或相对描述。
- 提交前自查 + CI 占位检查（ secret 扫描脚本按需建立）。
- 一旦发现密钥泄露入历史：立即吊销该密钥，再清理历史，并记录事故（CHANGELOG + ADR）。

## 3. 凭证存储

- API key 等凭证优先入**系统凭据管理器**（钥匙串/凭据管理器/secret 服务）；早期阶段允许权限收敛的本地配置文件（仅当前用户可读，0600 等价）。
- 配置文件中只存**引用**（如 `keyRef: keychain:<服务名>` 或 `$ENV:XXX`），不存明文。
- 日志与诊断输出必须脱敏（key/token/授权头一律遮蔽）。

## 4. 外部代码与沙箱（如项目执行三方代码/插件，按需保留）

- 默认无能力：文件、网络、执行、环境变量均须声明 + 用户逐项批准。
- fail-closed：未声明 = 拒绝；危险树（`.env*`、SSH 凭证、`.git/**`）硬拒。
- 动态加载代码默认禁止；能力以显式注入的受控接口提供。
- 每次能力拒绝与高风险授权必须留审计记录。

## 5. 工具执行安全（如项目有 agent/自动化工具，按需保留）

- 工具信任分级（只读/写入/执行）。
- 危险操作（删除、覆盖、不可逆命令）必须经用户确认通道；确认策略可配置但默认从严。

## 6. 供应链

- 依赖准入按 standards/04 §5；lockfile 入库；快速演进的依赖升级窗口化（每阶段最多一次、独立提交）。
- CI 视语言提供许可证冲突 / 已知漏洞检查（如 `cargo deny` / `npm audit` / `pip-audit`）。
- **外部源码许可证纪律**：GPL/LGPL 等强传染许可证项目源码严禁复制/翻译/结构性照搬，只读思路；MIT/Apache 等宽松许可证代码引用须保留版权与许可证声明并注明来源；任何第三方代码片段引入须满足依赖准入同等审查。

## 7. 事件与上报

- 项目默认**零遥测**；未来如加，默认关闭 + opt-in + ADR。
- 安全漏洞报告渠道：仓库私密 issue（暂定；公开分发后升级为独立邮箱/渠道，届时写 ADR）。
