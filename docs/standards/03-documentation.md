# 规范 03：文档规范（文档先行）

- 状态：定稿
- 日期：2026-10-30

## 1. 文档先行流程（硬规则）

1. 阶段开工前置：该阶段 phase 文档 + 其引用的设计文档状态 = **定稿**。
2. "定稿"判定：内容完整、验收场景可执行、遗留问题逐条列出或有归属。
3. 所有者不审技术细节，但拥有**知情权与叫停权**：阶段开工/收尾必须反映在 roadmap 看板与 CHANGELOG。
4. 实现中发现设计有误：先改文档/ADR（说明为什么错、改成什么），再改代码；禁止"代码先行为主"。

## 2. 文档头与状态

每篇文档头部包含：

```markdown
- 状态：草稿 | 评审中 | 定稿
- 日期：YYYY-MM-DD（最近定稿/更新日）
- 关联：相关 ADR / 文档链接
```

- 状态变更必须同步 `docs/README.md` 清单表与 CHANGELOG。
- 定稿文档可修订：小修直接改并更新日期；语义级变更须在文内注明"YYYY-MM-DD 修订：……"，不可逆项另写 ADR。

## 3. 文档类型与归属

| 类型 | 目录 | 规则 |
|---|---|---|
| 决策记录 ADR | docs/adr/ | 编号递增、只增不改；推翻旧决策写新篇并注明取代关系 |
| 架构设计 | docs/architecture/ | 描述"系统是什么、约束是什么"；与实现偏差即修订 |
| 阶段详细设计 | docs/design/phase-N/ | 每阶段实现前定稿（phase 文档"交付物"列出清单） |
| 路线图 | docs/roadmap/ | 阶段范围/验收；00-roadmap.md 是唯一进度看板 |
| 规范 | docs/standards/ | 违反规范的行为要么改正、要么先改规范（走 ADR）；规范自身的复查与进化走 standards/09 |
| 调研 | docs/research/ | 事实与数据沉淀；新调查追加新篇，不改旧篇结论（可加"更新"节） |
| 阶段进度报告 | docs/design/phase-N/report.md | 每阶段收尾产出（模板见 design/_report-template.md） |

> 另有 `briefs/`（仓库根，gitignore 不入库）存放所有者的参考与建议（与 AI 前期沟通的简报）：它**不是正式文档**，不承担事实来源职责；与 AI 对齐后的结论必须沉淀进上表对应区域（research / ADR / design / roadmap）才算数。规则见 `briefs/README.md`。

## 4. 写作要求

- 语言：中文（代码块、标识符、路径除外）；面向所有者的文档（README/CHANGELOG/进度报告）避免未解释的行话，术语链接 `docs/glossary.md`。
- **流水账禁令**：docs/ 内禁止一切追加式日志（会话记录、每日进展）；唯一流水账是根目录 CHANGELOG。过程笔记进 `.agents/`，体量预算见 standards/08。
- 图：架构与流程用 mermaid 内嵌。
- 模板（阶段设计稿）：背景 / 目标 / 方案 / 数据与接口定义 / 验收 / 风险 / 待决问题。
- 新增文档必须登记 `docs/README.md`；禁止产生孤儿文档；每阶段收尾核对清单与实际文件一致。

## 5. 附录：《阶段进度报告》要点（全模板见 design/_report-template.md）

完成成果（非技术语言）/ 验收场景逐条结果 / 架构接缝核对 / 体量核对（standards/08）/ 规范复查（standards/09 四问）/ 已知问题与风险 / 对下阶段的影响 / 文档更新清单。
