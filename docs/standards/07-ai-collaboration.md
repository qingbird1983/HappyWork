# 规范 07：AI 协作规范

- 状态：定稿
- 日期：2026-10-30
- 关联：AGENTS.md（入口摘要）；standards/01~06（各领域细则）

## 1. 冷启动原则

本项目由 AI 会话接力开发，**任何会话不得依赖"上一个会话的记忆"**：开工时按 AGENTS.md 顺序读文档；工作中产生的新事实/决策/风险必须当场落盘（research / ADR / design / 看板），不允许"留在对话里"。

## 2. 会话开工清单

1. 读 `.agents/CONTEXT.md` → `AGENTS.md` → `docs/README.md` → 当前 phase 文档 → `standards/` 相关篇。
2. 确认当前阶段状态（roadmap 看板）与本会话任务的关系：是推进当前阶段，还是维护性修改。
3. 检查工作区干净（版本控制状态检查）；从 main 拉新分支（已启用 git 时）。
4. 若发现文档与代码/事实不符：**先修文档或提 ADR**，再继续任务。
5. 若所有者指定了 `briefs/` 材料：先读、对齐方案、把一致结论沉淀进 docs/ 对应区域并回填 brief 状态（规则见 `briefs/README.md`）——brief 本身不作为事实来源，未沉淀的结论不算数。

## 3. 阶段生命周期中的 AI 职责

| 时点 | 职责 |
|---|---|
| 开工 | 核对开工前置条件（phase 文档 §3）；不满足则先补文档 |
| 设计 | 产出/修订 `docs/design/phase-N/` 并转定稿；重大取舍写 ADR |
| 实现 | 遵守 standards/04/05/06；feature 分支；小步提交 |
| 验收 | 逐条执行验收场景（含一票否决项）；架构接缝核对 |
| 收尾 | 《阶段进度报告》（含接缝核对、体量核对、**规范复查** standards/09）→ roadmap 看板 → CHANGELOG → tag `phase-N.end` |

## 4. 对所有者的沟通规则

- 所有者不读代码：汇报一律用《阶段进度报告》与 CHANGELOG 的"非技术语言"；必须使用术语时链接 `docs/glossary.md`。
- 需要所有者决策的事项集中列在 README"待决策"表，并在 CHANGELOG 条目中提醒。
- 坏消息优先：风险、延期、验收未过必须如实、尽早写入进度报告，禁止"报喜藏忧"。

## 5. 外部代码纪律

- 强传染许可证（GPL/LGPL 等）项目：严禁复制/翻译/结构性照搬其源码与文档文字；只允许参考公开文档描述的设计思路，实现须原创并注明"思路参考 docs/research/NN"。
- 宽松许可证（MIT/Apache 等）代码：可引用但必须保留版权与许可证声明；来源与用途登记在 research 或 ADR。
- 引入任何第三方代码片段（SO/博客等）须满足依赖准入同等的审查与登记（standards/04 §5、standards/06 §6）。

## 6. 范围纪律

- 只做当前阶段 phase 文档"做"清单内的事；发现高价值超出项 → 登记 backlog（roadmap §3）或新开 ADR，**不顺手实现**。
- 规范冲突时优先级：安全（06）> 测试硬义务（05）> 文档先行（03）> 其余。

## 7. .agents 交接与沉淀（每轮会话收尾必做）

规则全文见 `.agents/README.md`，预算受 standards/08 约束。摘要：

1. **重写** `.agents/CONTEXT.md`（覆盖式，模板 A）——下一轮会话的第一站。
2. **归档** handoff（≤80 行/份，滚动保留 5 份）。
3. **沉淀**：新坑 → pitfalls（一坑一文件，先查重）；新方法 → skills（一主题一文件）；**教训当轮提取，未提取即交接失败**。
4. **体量核对**：CONTEXT ≤150 行、.agents 全目录 ≤40 文件，超标当轮清理（可跑 `scripts/check-size`）。

正式知识（应让所有未来会话永久知道的）归宿是 docs/（ADR/架构/规范），.agents 只放过程与经验。
