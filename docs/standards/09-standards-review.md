# 规范 09：规范复查与制度进化

- 状态：定稿
- 日期：2026-10-30
- 关联：standards/01~08（被复查对象）；standards/03 附录（进度报告模板）；standards/08 §7（豁免登记）

## 0. 目的

本项目靠制度管理而非人治（所有者不读代码，制度是唯一防线），因此**制度本身也会出 bug**：有漏洞、有过严、有过松、会过时。规范必须自带"复查—修正—进化"的闭环，且复查流程自身受防膨胀约束。

**被复查对象**：standards/01~09 全部、根入口文件（README / AGENTS.md / CHANGELOG）、`.agents/README.md`。

## 1. 两种复查

| 类型 | 触发 | 范围 | 输出去向 |
|---|---|---|---|
| **例行复查** | 每阶段收尾，固定动作 | 被复查对象全部过一遍 | 《阶段进度报告》"规范复查"节 |
| **触发复查** | §2 任一信号出现，**当轮处置** | 涉事规范 | 当轮修订 + CHANGELOG |

## 2. 触发信号（出现即查，不等阶段末）

1. **漏洞信号**：发生违规或事故，而现行规范没能事先拦住——查清是"缺规则"还是"规则不可执行"。
2. **过严信号**：同一规则在一个阶段内被豁免登记 **≥2 次**（登记见 standards/08 §7）——处置对象是规则本身，不是续期豁免。
3. **过松信号**：同类问题重复出现 **≥2 次**、每次靠 AI 现场判断兜底——说明缺一条硬规则。
4. **失效信号**：上游（依赖、工具链、平台）或技术选型变化，使某条规则的前提不再成立。
5. **所有者信号**：所有者读文档后产生误解或提出疑问——**所有者读错的地方视为文档 bug**（所有者是文档的唯一验收人），当轮澄清或重写。

## 3. 复查四问（例行复查对每篇规范过一遍）

1. **有漏洞吗**——本阶段出现的坏结果，哪条规则本可拦截却没拦？
2. **过严吗**——哪条规则迫使做了无用功、或已被豁免？（豁免 ≥2 次的优先）
3. **过松吗**——哪类事还在靠"AI 自觉"而不是硬规则在管？
4. **冗余或矛盾吗**——规则之间、文档之间是否重叠或冲突？**矛盾即 bug，当轮修**。

没有发现的篇目如实写"无发现"，**不强行产出**。

## 4. 修正分级与流程

| 级别 | 判定 | 流程 |
|---|---|---|
| 笔误级 | 错字、失效链接、表述歧义 | 直接修订 + CHANGELOG 一句话 |
| 规则级 | 预算数字、流程步骤、清单增删 | ADR（可简短）+ 修订 + CHANGELOG；CHANGELOG 用非技术语言写清"改了什么、为什么" |
| 机制级 | 废除/新设一篇规范或一类机制 | ADR + CHANGELOG 置顶向所有者说明 |

- 修订任何规范时，**同步检查全部引用处**（AGENTS.md、docs/README.md、各篇"关联"行、.agents/CONTEXT.md），防止"改了正文、漏了引用"。
- 修订历史不另立流水：CHANGELOG 一条 + 必要时 ADR；规范正文保持覆盖式更新。

## 5. 防膨胀约束（复查机制管自己）

- 例行复查输出**有界**：只占进度报告一节，不产生新文档、不重写全文。
- 触发复查**当轮闭环**：发现→修订→登记在同一轮完成，禁止"记下来以后再说"。
- 复查频率有界：例行仅阶段末一次；触发复查以信号为据，**不做"预防性全盘重审"**。

## 6. 生效

- 触发复查即时生效；首次例行复查在**第一个实现阶段收尾**（初始化阶段已封板，不回溯）。
