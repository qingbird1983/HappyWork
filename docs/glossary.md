# 术语表

> 面向非技术读者。文档中每个首次出现的项目专有术语都应登记在此（登记义务见 standards/03）。
> 按拼音/字母排序；解释只用日常语言，不用另一个术语解释术语。

- 状态：草稿
- 日期：2026-10-30（Phase 4 立项补充审计/备份/签名术语）

| 术语 | 英文/别名 | 通俗解释 |
|---|---|---|
| Agent | 智能体 | 能替你完成一串电脑操作的 AI 程序：你给一句任务，它自己拆步骤、调工具、给你结果；本项目的 Agent 每做关键动作前要经你批准 |
| 会话 | Session | 你和 Agent 的一次完整对话，从给任务到出结果；所有过程记录都在会话里 |
| 回合 | Turn | Agent "想一步、做一个动作"的一轮；一个会话由多个回合组成 |
| 工具 | Tool | Agent 能使用的具体能力，比如读文件、发网络请求；每个工具都要登记风险等级 |
| MCP | Model Context Protocol | 一个让 Agent 接入外部工具的通用插座标准；本项目先只接本机运行的 MCP 服务 |
| 审批 | Approval | Agent 要做有风险的动作时，弹出说明请你点"允许/拒绝"；说明里必须写清它想动什么、能不能撤销 |
| 可逆性 | Reversibility | 一个动作做错了能不能退回来。写文件可以恢复，发出去的邮件收不回——后者就是"不可逆"，风险最高 |
| 匹配指纹 | matchKey | "这次批准管多大范围"的记号：比如"本会话内写 docs 文件夹都不再问"，记的是范围，不记具体内容 |
| 执行锁定 hash | execHash | 把"批准时看到的参数"算成一串指纹，执行前再算一次，两次不一致就拒绝执行——保证"你看到的就是它做的" |
| TOCTOU | time-of-check to time-of-use | "检查时是一个样、使用时变成另一个样"的漏洞类型：审批时看着安全，执行时参数或路径被偷换 |
| JCS | JSON Canonicalization Scheme | 给 JSON 数据定唯一标准写法的规则（RFC 8785），保证同一份数据在哪儿算指纹都一样 |
| 路径规范化 | path canonicalization | 把文件地址统一成唯一标准写法，堵住用快捷方式、大小写、缩写名把"允许的目录"偷换成"任意目录"的花招 |
| 沙箱 | sandbox | 给程序划一个"活动围栏"，护栏内的程序碰不到外面的文件和网络 |
| 备份式回滚 | backup rollback | 改文件前先留一份旧副本、删除先进回收站——出错时可以退回原样 |
| 备份版本 | backup version | 同一个文件每被改一次就多留一份旧内容，按次数编号；可以挑任意保留的版本退回去 |
| 审计链 | audit chain | 每条安全记录都带上一条记录的指纹，像链条一样串起来；改动、删除或插队中间一条会被发现 |
| 追加只读 | append-only | 只允许在末尾新增，不允许改写或删除已有记录；本项目用数据库触发器强制执行 |
| 软上限 | soft quota | 达到后拒绝继续新增、而不是偷偷删旧数据的容量上限；本项目备份区为 512 MiB |
| 代码签名 | code signing | 用证书给程序"盖章"，证明它来自谁、发布后没被改过；Windows 用 Authenticode |
| 公证 | notarization | Apple 对 macOS 应用做的云端安全检查；通过后系统才更愿意放行 |
| dry-run | 预演/空跑 | 用临时测试凭据把签名流程完整走一遍，但不发布正式产物 |
| 会话记录 | transcript | Agent 每一步"说了什么、做了什么、谁批准的"的完整流水账，只增不改，恢复会话靠它 |
| 幂等键 | idempotency key | 给每个动作发唯一编号，同一编号最多执行一次——重试时不会把文件写两遍、邮件发两封 |
| Wails | — | 让 Go 语言写的程序套上网页界面、变成桌面应用的框架；本项目用它做三平台的桌面壳 |
| WebView | — | 操作系统自带的"迷你浏览器"组件，桌面应用用它显示界面，不用额外打包整个浏览器 |
| 看板 | board | 记录每个阶段做到哪了的表格，只在此处维护 |
| ADR | decision record | "决策记录"——把一次重大技术选择的背景、决定和理由写成一篇短文，编号保存，只增不改 |
