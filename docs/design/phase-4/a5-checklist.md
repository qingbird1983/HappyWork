# A5 真机验收操作清单（审计面板 + 备份面板）

> 状态：**已代跑完成（2026-10-31，所有者授权）**；结果与证据见 [report.md](report.md) §2 A5 与 §4.19。本文保留为复验/回归流程。
> 目的：在**隔离数据目录**里用真实 GUI 走一遍 Phase 4 的审计与回滚能力。
> 自动化测试已覆盖同一批行为（`docs/design/phase-4/report.md` §2），这里只验"人看得懂、点得动、提示说得清"。
> 每一步都写了「怎么做」和「应当看到什么」。看不到预期结果就停下记下来，不要继续往下点。

## 0. 准备（不污染日常环境）

1. 新建两个空文件夹，例如：
   - 隔离数据目录：`D:\hw-a5\appdata`
   - 测试工作区：`D:\hw-a5\ws`
2. 在 PowerShell 里这样启动（`APPDATA` 决定 HappyWork 的数据目录，只对这次启动生效）：

   ```powershell
   $env:APPDATA = "D:\hw-a5\appdata"
   $env:DEEPSEEK_API_KEY = "你的密钥"      # 只放在这次会话的环境变量里，不要写进任何文件
   & "E:\Warehouse\AIwork\HappyWork\bin\happywork.exe"
   ```

3. 应用里把工作区指向 `D:\hw-a5\ws`，新建一个会话。

应当看到：正常启动、能建会话；`D:\hw-a5\appdata\happywork\` 下出现数据库文件。

## 1. 触发一次写文件审批

对模型说：`在工作区里新建 note.txt，内容为第一版`。

应当看到：弹出审批框，里面显示的是**相对路径**（`note.txt`），不是 `D:\hw-a5\ws\note.txt` 这样的完整路径；选择"仅本次允许"。

## 2. 打开「审计 / 备份」面板

点顶栏的**审计 / 备份**按钮。

应当看到：
- 审计标签页里有一条链状态徽章，文字是「链状态：完整」（若显示"破损"就是缺陷，记下徽章下方横幅里"第 N 条起中断"的 N）。
- 记录列表至少出现三类：`tool_call` + `ask`、`approval` + `allow`、`backup` + `create`；时间/动作/决策/原因四列都读得懂，正文里不出现文件内容。

## 3. 验证整链

点**验证整链**按钮。

应当看到：状态仍是「完整」，密封条数 ≥ 列表条数；如果历史里有 Phase 4 之前的旧记录，徽章应写"（N 条旧记录未密封）"而不是假装全部可信。

## 4. 导出证据并检查隐私

点**导出证据**，记下界面给出的导出路径，用记事本打开那个 `.jsonl`。

应当看到：
- 每行一条 JSON，行数与面板里的记录数一致；旁边还有一个 `.manifest.json`。
- **通篇不出现** `D:\hw-a5\ws`（工作区绝对路径）和 `note.txt` 里的正文"第一版"。出现了就是 P-013 那类回归，截图并记下在哪一行。

## 5. 覆盖写 → 看版本列表

对模型说：`把 note.txt 内容改成第二版`（同样批准）。

应当看到：备份标签页里 `note.txt` 出现 2 个版本，较早那条带"恢复"按钮，新建那条带"撤销创建"按钮。

## 6. 恢复（含安全副本）

点第一版的**恢复**，先看确认提示再确认。

应当看到：
- 确认框说明"恢复前会先把当前内容存成新版本"，不是直接覆盖。
- 恢复后 `D:\hw-a5\ws\note.txt` 内容回到"第一版"；备份列表多出一个"安全副本"版本，**带"恢复"按钮**（恢复本身可再撤销；修复前它显示"未确认"且没有按钮，见 P-020）。
- 审计页新增 `backup` + `restore` 记录。

## 7. 撤销创建

让模型新建 `tmp.txt`，批准后在备份面板点它的**撤销创建**。

应当看到：
- 工作区里 `tmp.txt` 消失；
- 确认框写的是"移入备份区，不会永久删除"；在 `D:\hw-a5\appdata\happywork\backups\<sessionID>\discarded\tmp.txt\` 下能找到它（实际路径在备份区，不是 `happywork\discarded\`），内容仍是原来的；
- 审计新增 `backup` + `undo_create`。

## 8. 运行中拒绝恢复

让模型连续做多步任务（或等它正在跑），期间点**恢复**。

应当看到：按钮置灰或提示"会话运行中，暂不能恢复/撤销"；界面不卡死、不出现半成品状态。

## 9. 重启与中断标注（可选）

任务正在跑时从任务管理器结束 `happywork.exe`，再用同样方式启动。

应当看到：中断的回合被标成"已中断/状态未知"而不是假装完成；审计里出现 `recovery` 记录。

## 我要你回报的 6 件事

1. 链状态徽章与破损横幅（若有）文字；
2. 导出的 JSONL 里是否出现绝对路径或文件正文；
3. 恢复后面板是否真的多出一个"安全副本"版本；
4. 撤销创建后 `discarded\` 里能否找到文件；
5. 运行中点的提示语原文；
6. 任何看不懂或觉得会误点的文案。

## 代跑结果（2026-10-31，隔离数据目录 `D:\hw-a5\appdata` + 工作区 `D:\hw-a5\ws`）

1. **链状态徽章**：始终为「链状态：完整」，最终「密封 17 条 · 遗留 0 条」，无破损横幅；`验证整链` 提示「审计链验证通过」。
2. **导出隐私**：两份导出（3 条、16 条、17 条）均无工作区绝对路径（`hw-a5` 命中 0）、无文件正文（`第一版/第二版/第三版/临时文件` 命中 0）、无盘符（`D:` 命中 0）；manifest `ok: true`、`headMatch: true`。
3. **安全副本**：恢复后出现安全副本；**首次发现它被标成「未确认」且没有恢复按钮（缺陷，已修复为「安全副本 + 恢复」）**。修复后实际点了一次安全副本的恢复，`note.txt` 回到「第二版」，原安全副本变为「已恢复/已撤销」，并生成了新的安全副本。
4. **撤销创建**：`tmp.txt` 从工作区消失，内容在 `backups/<sessionID>/discarded/tmp.txt/…trash`（13 B，内容「临时文件」）；审计新增 `backup/undo_create`。
5. **运行中提示**：原文「会话正在运行；请先停止，再恢复或撤销创建。」，恢复/撤销按钮置灰；界面不卡死。
6. **其它观察**：`确认` 按钮用自动化鼠标点击两次未触发、键盘（Shift+Tab/Return）可正常激活——未在真人口述中复现，先记为自动化坐标的待复核项；模型在总结时误称 `note.txt` 为「第二版」（实际是「第一版」），属于模型未重读文件，不是 UI 缺陷。
