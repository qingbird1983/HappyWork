# .agents —— AI 开发知识库与交接中枢

- 定位：AI 会话接力的**工作记忆**——上下文交接、踩坑沉淀、可复用方法。服务对象是 AI 会话；项目所有者可读但无需维护。
- 与 `docs/` 的分工：**docs/ = 正式事实**（活性文档、覆盖式修订、有评审）；**.agents/ = 工作过程**（易腐、可删、版本历史即归档）。正式知识必须沉淀进 docs/（ADR/架构/规范），.agents 只留过程与经验。
- 体量纪律：本目录受**硬性预算**约束（见 §3），与 `docs/standards/08-size-control.md` 同级生效。

## 1. 目录与生命周期

| 路径 | 是什么 | 生命周期 |
|---|---|---|
| `CONTEXT.md` | **当前**工作上下文交接卡（全库唯一一份） | 覆盖式更新：每轮会话收尾整体重写，不追加 |
| `handoff/` | 历史交接归档（`H-NNN-短主题.md`，三位递增编号） | 滚动保留**最近 5 份**；教训提取后更早的直接删除 |
| `pitfalls/` | 踩坑沉淀（一坑一文件，`P-NNN-短slug.md`） | 长期；同类坑更新原文件；失效即删 |
| `skills/` | 可复用方法沉淀（`S-NNN-*.md`）；vendored 第三方技能放独立子目录（不计预算，须注明来源与许可证） | 长期；过时即删 |

## 2. 每轮会话收尾必做（缺一即交接失败）

1. **重写 `CONTEXT.md`**（用 §4 模板 A）。
2. **归档交接**：把本轮有价值的交接存为 `handoff/H-NNN-*.md`；**教训当轮必须提取**进 pitfalls/skills——未提取的教训不允许只留在 handoff 里。
3. **沉淀**：新坑 → `pitfalls/`（先检索去重）；新方法 → `skills/`。
4. **体量核对**：按 §3 预算自查（可跑 `scripts/check-size`），超限当轮清理。

## 3. 防膨胀预算（硬数字，超标当轮强制清理）

| 对象 | 上限 | 说明 |
|---|---|---|
| `CONTEXT.md` | ≤ 150 行 | 覆盖式；写不下一律是"该沉淀的没沉淀" |
| `handoff/` 单份 | ≤ 80 行 | 只保留最近 5 份 |
| `pitfalls/`、`skills/` 单篇 | ≤ 80 / 120 行 | 超限=没提炼；模板外的长材料放链接 |
| `.agents/` 全目录（不含 vendored 技能子目录） | ≤ 40 个文件 | 超限触发整合评审（合并/删除） |
| 新增条目前置 | 先检索 | 与既有条目同主题→更新原文件，禁止平行开新文件 |

判废标准（任一即删/改）：条目描述的问题已不可能再发生；方法已被规范/ADR 吸收为正式规则；文件超过保留期且教训已提取。

## 4. 模板（以下内联，使用时按此结构创建文件）

**模板 A —— `CONTEXT.md` 交接卡：**

```markdown
# 工作上下文交接卡
- 更新：YYYY-MM-DD（会话主题：一句话）
## 当前阶段与状态（对照 roadmap 看板）
## 上一轮完成了什么（3~5 条）
## 下一步（按优先级，注明阻塞项）
## 未决问题
## 关键提醒（坑/规范变更/易错点，链接 pitfalls 编号）
```

**模板 B —— `pitfalls/P-NNN-*.md`：** 现象 / 根因 / 修复 / 预防（怎么不再犯，指向规范或代码位置）/（如复发）再次发生记录。

**模板 C —— `skills/S-NNN-*.md`：** 适用场景 / 前置条件 / 步骤 / 验证方法 / 失效条件（什么时候此法不再适用）。

**模板 D —— `handoff/H-NNN-*.md`：** 日期与主题 / 本轮做了什么 / 验证 / 遗留与下一步 / 已提取的沉淀编号（P/S-NNN）。

## 5. 纪律

- 不得写入：密钥、个人绝对路径、客户隐私（同 `docs/standards/06-security.md`）。
- 本 README 的规则修改视同规范修改：走 `docs/standards/08` 修订流程，不悄悄改。
- .agents 不是第二个 docs：一切"应该让所有项目会话永久知道"的东西，归宿是 docs/（ADR/架构/规范）。
